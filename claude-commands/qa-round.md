# qa-round — S1 测试单轮

你是本仓的测试会话。一轮只走查一个模块/一条 e2e 路径,干完收尾,由 /loop 调度下一轮。

## 0. 轮转状态

读 `.scratch/qa-round.txt`(不存在则创建,写入 `tool:0`)。内容格式 `轨道:序号`:
- `tool:N` — 本轮走工具/API 层 e2e 清单第 N 条
- `ui:N` — 本轮走 UI 模块清单第 N 条
本轮结束后推进到下一项(清单循环),两轨交替。

工具/API 层清单(**按你的项目替换**,示例):
1. 核心 API 面:健康检查 → 建资源 → 读 → 改 → 删
2. 关键业务链路 A(mock 档)
3. 关键业务链路 B(mock 档)
4. 导出/产物链路(本地小样)
5. 高频交互路径(增删改 + undo 类操作)

UI 模块清单(轮转,按你的项目替换):核心面板/页面的可用性与报错路径。

## 1. 档位与预算

- **mock 档**(默认):不真调外部付费服务,走 mock/本地路径,免费高频。
- **真调档**:读 `.scratch/qa-budget.json`(不存在则建 `{"date":"<今天>","expensive":0,"other":0}`)。当天 `expensive>=2` 则贵服务类一律 mock;`other>=10` 则其余真调一律 mock。真调一次即给对应计数 +1 并写回。

## 2. 走查与提单

发现疑似 bug 时,**提单前必须锚点自查**(三层防线第一层):
1. 确定结构化锚点:`mod:*` 标签 + 涉及文件/工具名 + 复现路径
2. `gh issue list --repo OWNER/REPO --state open --label <mod标签> --json number,title,body` 后比对锚点;再全量扫一遍 open 单标题防跨模块重复
3. **已存在同锚点 open 单** → 不新建,在该单评论补充证据(第几轮走查、新日志/截图路径),本轮结束
4. 不存在 → `gh issue create`,标题 `[<模块>] <现象>`,正文必含:涉及工具/路由、复现步骤、期望与实际、代码位置(文件:行)、优先级建议、根因初判。标签:`bug`、`from:qa`、`claude-ready`(S1 单按构造即可就绪:复现可验证+代码位置有出处)、`mod:*`、`priority:pN`(p0=阻断主流程/p1=明显不符/p2=体验问题)
5. 根因在外部服务/额度/第三方的 → 打 `deferred:external`,不入修复池

## 3. 纪律

- 一轮一个模块,不提增强类单(enhancement 由人提)
- 证据先行:日志、截图、命令输出贴进 issue;无稳定复现先复现再提
- 发现**同一根因在多处表现**:提一单作根因 issue,正文列「关联现象清单」,不自建重复单
- 收尾:更新轮转状态文件,汇报本轮结果(走查对象/新提单号/补证据单号),并建议下一轮 /loop 间隔(有发现 5-7 分钟,无发现 15-30 分钟)
