# 00 · 概念全景

## 这套系统是什么

一个「单人开发舰队」的完整操作系统:

- **GitHub 是唯一账本**——issues 是任务队列,PR 是交付物,标签是状态机,Actions 是云端工人;
- **Claude Code 会话是工人**——每个角色一个会话,由 `/loop` 驱动常驻,单轮命令定义它的全部行为;
- **CLAUDE.md 是宪法**——写进仓根的纪律文件,所有会话每次启动必读;
- **人是老板**——只保留裁决权、chore 合并权、开火权(随时可以关掉任何会话)。

核心理念:**把「写代码」之外的整条生产线(分诊、修复、核实、审查、合并、巡逻)全部自动化,人的注意力只花在必须人开口的例外上。**

## 状态机(标签即状态)

issue 的一生(正常路径):

```
新建 → (triage 分诊/QA 自查) → claude-ready
     → S2 认领 status:doing
     → 提 PR status:fixed
     → S3 核实 status:verified
     → S4 自动合并 + 显式关单(closed)
```

异常分支(每条都有归属人):

| 状态 | 含义 | 归属人 |
|---|---|---|
| `status:rework` | 被打回(核实不过/审查红线) | S2 最优先认领返工;**裁决类红线转 question** |
| `question` | 必须主人开口(熔断/歧义/ADR 冲突) | S5 裁决会 |
| `needs-info` | 信息不足 | 提单人补料,补后自动重分诊 |
| `duplicate-candidate` | 疑似重复 | 高置信自动关,低置信等主人确认 |
| `deferred:external` | 根因在外部服务/额度 | 挂起,S5 定期清点 |
| `circuit:collateral` | 熔断连坐(非本身缺陷) | S3 连坐恢复池自动恢复 |
| enhancement 无 ready | 改进建议待排期 | S5 裁决会排期 |

**设计律:每个状态都必须有归属人;「等主人」也必须带上报通道和超时,否则等于无人管。**

## 五条设计律(为什么是这套形状)

### 1. 实现者 ≠ 验证者

GitHub 平台禁止 PR 作者批准自己的 PR;Google 工程实践「评审的终点是另一名工程师同意」;Meta「每个改动必须被评审,没有例外」;Anthropic 官方文档原话 "the agent doing the work isn't the one grading it"。

落到舰队:S2(实施)和 S3(核实)必须是**两个独立会话**,S3 有独立 worktree、独立端口,不轻信 S2 的自述,一切结论以复现为准。

### 2. 组合态才算数

一个 PR 的 CI 绿,是「这个分支 + 当时的 main」的绿。两个各自绿的 PR 合体后,main 可能红——GitHub 不会在 base 前进后自动重算。所以:

- S4 合并后,下一轮必须核「本次合并 push 触发的 main CI」;
- 红 = p0 阻断,熔断(本轮不再合并)+ 提单 + 连坐处置(同批已合 PR 的 issue 打 rework + `circuit:collateral`);
- main 回绿后,S3 连坐恢复池自动恢复被连坐的单。

### 3. 验证信号必须有失效语义

GitHub 对 approval 有 stale dismissal(新提交即作废),标签没有。所以 S3 打 verified 时必须附**锚定行**(`核实锚定:head <sha> / 基底 main <sha>`),S4 合并前做**新鲜度两查**:head 变了 → verified 作废重核;基底旧了 → update-branch 重跑 CI。

### 4. 自动化的是发现与上报,不是替人拍板

所有会话共用主人的 gh 登录态——任何一个「授权标签」都无法区分是人打的还是机器人自己打的。所以**绝不设「机器人可自我授权」的通道**;人的授权只发生在当面(裁决会、当面一句话)。机器人能做的是:把一切需要人开口的事,准时、完整、带证据地摆到人面前。

### 5. 机制与产物同仓,文档即代码

命令文件(`.claude/commands/`)、workflow、CLAUDE.md、ADR 全部版本化管理,改动走 PR(机制类 PR 永不自动合并,人工把关)。每条机制文档必须在注释里写明「为什么」——通常是一次事故的单号和根因。**注释里的血泪教训是这套机制的灵魂。**

## 运行机制:单轮命令 + /loop

每个角色 = 一个 Claude Code 会话 + 一个单轮命令文件 + `/loop` 自调度:

```
/loop 15m /fix-round
```

- 会话每轮干一件事(认领一单/核实一单/扫一轮 PR),干完收尾;
- 收尾前必须给自己排下一轮(ScheduleWakeup,动态间隔:忙 10 分钟、闲 15-30 分钟);
- 会话死了不会自动复活——这正是看门人(`/monitor-round`)存在的理由:三环心跳 + 超时上报 + 自报心跳文件。

## 上下文纪律

- 一轮只做一单,做完收尾——上下文不跨单积累;
- 命令文件是「单轮剧本」,每轮重新加载,机制改进即改即生效;
- 长任务(大功能)走直管 worktree 会话,不进流水线,完成后按直管 PR 通道交付核实(见 docs/06)。
